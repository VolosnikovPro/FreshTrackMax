1. Назначение
Документ описывает перечень доработок текущей версии FreshTrack по результатам тестового запуска. Сгруппирован по трём блокам: архитектурные решения, права доступа по ролям, изменения интерфейса и логики. Раздел 8 — открытые вопросы, требующие согласования до начала работ.
2. Архитектурные решения (применяются ко всей системе)
2.1. Мультиобъектность
Ввести сущность «Объект». Все записи (продукты-остатки, партии, расход, питающиеся, себестоимость, уведомления) привязываются к объекту. Пользователь видит и редактирует данные только своего объекта; права кросс-объектного доступа — см. п. 8. Пилотная эксплуатация — на одном объекте (Асача), но модель данных и фильтры реализуются мультиобъектными сразу, без последующей переделки.
2.2. Метод списания остатков — FEFO
При списании расхода между партиями одного продукта первой уменьшается партия с ближайшим сроком годности (First-Expired-First-Out). При исчерпании партии остаток переносится на следующую по сроку.
2.3. Нулевые остатки — архивирование, не удаление
Партии с нулевым остатком не удаляются физически, а получают статус «Архив»: скрываются из активных списков, фильтров «Срочно/Планово» и из уведомлений, но сохраняются в базе для истории расчётов и аудита. Формулировка из исходной идеи «система автоматически удаляет продукты с нулевым остатком» заменяется на «автоматически архивирует».
2.4. Защита от отрицательного остатка
Если в импортируемой накладной расход по продукту превышает суммарный доступный остаток по всем партиям — строка не списывается, остаток не уходит в минус, событие фиксируется в логе ошибок импорта с указанием продукта, требуемого и доступного количества.
2.5. Идемпотентность импорта
Повторный импорт накладной за уже загруженную дату не должен создавать дубли. Поведение по умолчанию — замена ранее загруженных данных за эту дату (с пересчётом остатков). Окончательное поведение — см. п. 8.
3. Роли и права доступа
Общее правило для всех ролей: редактирование уже созданных партий, сроков годности и продуктов запрещено. Изменение возможно только добавлением новой записи (новой партии). Удаление партий доступно только Администратору.

4. Обмен данными и обновление остатков
4.1. Приход (риск-отчёт)
Кладовщик ведёт риск-отчёт (Google Sheets / .xlsx) с колонками: продукт (артикул/название), количество, срок годности, Номер УПД (идентификатор партии). Импорт типа «Риск-Отчёт» создаёт новые партии или пополняет существующие. Поле, ранее называвшееся «Номер партии», во всех окнах переименовать в «Номер УПД».
4.2. Расход (ежедневный импорт накладных)
    • Источник — накладная внутреннего перемещения на столовую и магазин, импортируется кладовщиком ежедневно.
    • Сопоставление — расход сопоставляется с приходом по артикулу/названию продукта (УПД на стороне расхода не требуется).
    • Действие — система уменьшает остатки соответствующих партий по методу FEFO (п. 2.2).
4.3. Архивирование
После списания партии до нуля — автоматический перевод в статус «Архив» (п. 2.3).
4.4. Единицы измерения
Допущение: расход и приход указываются в одной единице измерения по продукту. Если в накладной возможны другие единицы (г/кг, мл/л) — требуется таблица коэффициентов пересчёта (см. п. 8).
5. Расчёт себестоимости
5.1. Себестоимость дня
Источник данных — ручной ввод Управляющего ПП (НЕ импорт расхода): за каждую дату вносятся (а) количество питающихся и (б) сумма накладной без НДС по столовой. Расчёт: себестоимость дня = сумма накладной без НДС ÷ количество питающихся. Магазин в расчёт себестоимости дня не входит. Дни с нулём питающихся в расчёте не участвуют (деление не выполняется).
5.2. Средняя себестоимость за месяц
Средняя = среднее арифметическое дневных себестоимостей за месяц: сумма значений «себестоимость дня» ÷ количество дней, по которым есть данные. (Не средневзвешенная по питающимся.)
5.3. Отображение
Раздел «Себестоимость» (для УОП) выводится таблицей: строка на дату — «Дата | Себестоимость дня», и итоговая строка «Среднее за месяц».
6. Уведомления (бот МАХ)
    • Срочное — продукты со сроком ≤ 15 дней или просроченные. Рассылка всем участникам бота: срочно пересмотреть меню и включить продукты в использование; для товара магазина — уценка.
    • Плановое — продукты со сроком 16–45 дней. По товару магазина — уценка для быстрой реализации, замена ценников на цветной (красной) бумаге. По товару столовой включить продукты в план меню
Границы зафиксировать без пересечения: срочное ≤ 15; плановое 16–45. В текущей инструкции указаны «< 16» и «< 46» — привести к единым границам. Список получателей и привязка к ролям — см. п. 8.
7. Изменения интерфейса по ролям
7.1. Администратор
    • Добавить возможность полного удаления отчётов (загруженных импортов).
7.2. Кладовщик
    • Разрешить добавление нового продукта.
    • Добавить поиск в окне «Партии».
    • Запретить редактирование готовых партий, сроков годности, продуктов.
    • Раздел внесения движения переименовать в «Расход сырья»; работа — через ежедневный импорт накладных (требует визуальной сверки с текущей сборкой, см. п. 8).
7.3. Управляющий ПП (УПП)
    • В «Расходе» оставить только два поля: дата и общая сумма (без НДС). Поля и строки по отдельным продуктам убрать.
    • Закрыть доступ к разделам «Продукты» и «Партии».
7.4. Управляющий ОП (УОП)
    • «Продукты» и «Партии» — только режим просмотра.
    • Убрать ввод/редактирование питающихся (только агрегированный просмотр).
    • Дашборд: срочные и просроченные позиции (≤ 15 дней), себестоимость дня, средняя себестоимость.
    • Раздел «Себестоимость» — таблица по датам + строка среднего (п. 5.3).
7.5. Общие переименования
    • Во всех окнах добавления продукта/партии: «Номер партии» → «Номер УПД».
